오라클 DB 데이터 동기화 MCP 서버 개발 결과 보고서
1. 프로젝트 개요
본 프로젝트는 AI 에이전트가 폐쇄망 및 사내망(ai-hub) 환경에서 두 개의 서로 다른 오라클 데이터베이스(Oracle DB) 간에 데이터를 자동으로 동기화할 수 있도록 지원하는 MCP(Model Context Protocol) 서버를 개발하는 것을 목표로 하였습니다.

소스 DB에서 특정 조건(WHERE)을 만족하는 데이터를 추출하고, 타겟 DB에 테이블이 존재하지 않을 경우 스키마를 동적으로 생성한 뒤 데이터를 안전하게 이관하는 원클릭 자동화 프로세스를 구현했습니다. 특히, 오라클 11g와 같은 레거시 데이터베이스 환경을 완벽히 지원하며, 데이터 이관 중 발생할 수 있는 무결성 에러(Primary Key 중복 등)를 우회하는 강건한(Robust) 아키텍처를 채택하였습니다.

2. 시스템 아키텍처 및 환경 제어
2.1. 하이브리드 듀얼 실행 모드 (지연 초기화 적용)
운영 플랫폼(ai-hub 런타임)과 개발자 로컬 테스트 환경의 충돌을 방지하기 위해 지연 초기화(Lazy Initialization) 아키텍처를 도입했습니다.

점검 모드 (CLI): --check 또는 --call 플래그를 통한 단독 실행 시, MCP 서버 인스턴스를 메모리에 올리지 않고 즉시 DB 동기화 로직만 실행합니다. 이를 통해 JSON-RPC 프로토콜 간섭 없이 터미널에서 순수 파이썬 로직 테스트가 가능합니다.
서버 런타임 모드 (STDIO): 플랫폼 환경에서 인자 없이 실행될 경우에만 MCP 서버 객체를 생성하고 표준 입출력(stdio)을 통해 AI 에이전트와 통신을 시작합니다. SDK 버전 차이로 인한 데코레이터(@app.list_tools()) 에러를 원천 차단했습니다.
2.2. 오라클 11g 레거시 통신 지원 (Thick Mode)
파이썬의 최신 oracledb 라이브러리는 기본적으로 12c 이상의 DB만 지원하는 Thin 모드로 동작합니다. 오라클 11g DB와의 통신 제약을 극복하기 위해 Oracle Instant Client 19c (Thick 모드) 연동 로직을 추가했습니다. 클라이언트 경로를 코드 내 하드코딩하지 않고, Tool 호출 시 oracle_client_dir 파라미터로 동적 주입받도록 설계하여 폐쇄망 배포 시 라이브러리 벤더링(Vendoring)에 유연하게 대응할 수 있습니다.

3. 주요 기능 상세 및 동기화 프로세스
데이터 동기화 도구(db.sync_table)는 AI 에이전트의 단일 호출 시 아래의 7단계 프로세스를 롤백 없이 자동으로 수행합니다.

1단계 (소스 DB 연결): 전달받은 DSN 및 계정 정보로 소스 데이터베이스에 접속합니다.
2단계 (테이블 구조 분석): ALL_TAB_COLUMNS 데이터 딕셔너리를 조회하여 대상 테이블의 컬럼명, 데이터 타입(VARCHAR2, CHAR 등), 길이 정보를 동적으로 파악합니다.
3단계 (데이터 추출): 사용자가 전달한 where_condition 파라미터(예: ID > 100)를 적용하여 조건에 맞는 레코드 셋을 메모리로 추출합니다. 터미널의 띄어쓰기 파싱 에러를 방지하기 위해 이스케이프 처리된 JSON 형태를 지원합니다.
4단계 (타겟 DB 연결): 타겟 데이터베이스 세션을 엽니다.
5단계 (동적 DDL 생성 및 테이블 셋업): 타겟 DB의 ALL_TABLES를 검사하여 동일한 테이블이 없을 경우, 2단계에서 추출한 스키마 정보를 바탕으로 CREATE TABLE 구문을 즉석에서 조합하고 실행하여 테이블을 생성합니다.
6단계 (Fault-Tolerant 데이터 적재): 추출된 레코드를 타겟 테이블에 INSERT 합니다. 이때 executemany() 대신 단건 루프 방식을 채택하여 oracledb.IntegrityError(기본키 중복 등 무결성 위반) 발생 시 프로세스를 중단하지 않고 해당 건수만 무시(Bypass)한 채 다음 레코드를 계속 적재합니다. 최종적으로 정상 적재 건수와 중복 건너뜀 건수를 분류하여 리포팅합니다.
7단계 (트랜잭션 커밋 및 결과 반환): 모든 정상 데이터의 COMMIT을 수행하고 프로세스 수행 로그를 반환합니다.
4. 보안 통제 및 안전장치 (Safety Guards)
데이터베이스의 상태를 변경하는 쓰기(WRITE) 작업이 포함되어 있으므로, 오작동 및 보안 사고 방지를 위한 강력한 안전 통제를 적용했습니다.

4.1. 매니페스트 보안 정책
mcp-server-manifest.json에 해당 Tool의 위험 수준을 "risk_level": "WRITE"로 명시하였으며, 자동 실행을 방지하기 위해 "confirmation_policy": "ALWAYS"를 강제했습니다. 이로써 플랫폼 내에서 AI 에이전트가 단독으로 DB 데이터를 덮어쓰거나 수정하는 것을 막고, 반드시 관리자(사용자)의 최종 승인 프롬프트 창을 거치도록 설계되었습니다.

4.2. CLI 이중 잠금장치
단독 모드로 실행할 때에도 명령어 끝에 명시적인 --yes 플래그를 입력하지 않으면 실행이 거부되도록 파이썬 코드 레벨에서 이중 잠금장치를 구현했습니다.

5. 기대 효과 및 결론
본 MCP 서버의 도입을 통해 이기종 오라클 DB 간의 데이터 마이그레이션 및 동기화 작업이 자연어 지시만으로 가능해졌습니다. 특히, 운영 환경의 스키마 변경 사항을 일일이 수동으로 맞출 필요 없이 AI가 스스로 판단하여 테이블을 생성하고 중복 데이터를 안전하게 걸러내는 지능형 파이프라인이 구축되었습니다.

또한 완벽한 환경 변수 독립성과 하이브리드 아키텍처를 갖춤으로써, 추후 사내 ai-hub 플랫폼에 어떠한 코드 수정 없이도 즉시 배포하고 구동할 수 있는 높은 호환성과 완성도를 확보하였습니다.
